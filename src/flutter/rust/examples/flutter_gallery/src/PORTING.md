# Porting contract — flutter/gallery → rustflutter

Upstream: flutter/gallery @ d12640d (reference clone:
`D:/linzjUbuntu2204/gallery_upstream`). This is a working contract, not
documentation. Terse on purpose.

## Mapping rule

Every non-generated `lib/**.dart` file gets a same-relative-path `.rs` file
under `src/`. Each ported file carries a header comment naming its upstream
source file and the pinned commit. Generated files name their generator
instead and say "do not edit by hand".

Current mapping:

  `tools/gen_catalog.py`; its strings resolve to English only)

## Scope decisions (confirmed)

- **l10n**: structure-aligned, English-only. The 76 non-en locale files under
  `lib/l10n/` become documented placeholders, not ports.
- **codeviewer**: `code_segments` data is tool-generated, never hand-ported.
- **feature_discovery** and **deferred_widget** are in scope. Deferred loading
  becomes a synchronous equivalent — a documented divergence.

## Conventions

- **State**: one `GalleryState` + `StateHandle` at the root today
  (`src/app.rs`). Per-demo `State` where upstream has a per-demo `State`.
- **Hit-test ids**: allocated from the fixed `ids` bases in `src/app.rs`,
  never from a counter — an id must be stable across rebuilds.
- **Components**: one StatefulComponent per upstream StatefulWidget where
  feasible.
- **Anchors**: comments name upstream symbols (the way PORTING_STATUS.md
  does), not line numbers.
- **Divergences**: any unavoidable divergence gets a header comment at the
  site plus an entry in the log below. Silent skips are not allowed.

## Divergence log

- **one-screen-per-study**: each study is one representative screen, not the
  whole app (`src/studies/`).
- **studies-share-gallery-theme**: the studies' own themes are not ported;
  they run under the gallery's theme.
- **l10n is English-only**: the structure is ported
  (`src/l10n/gallery_localizations.rs` is the lookup surface, backed by the
  generated English table), but `GalleryLocalizations::lookup` resolves every
  locale to English and the other 76 locale modules are placeholders. Strings
  that predate the catalogue (`src/data/demos.rs` titles/descriptions, page
  chrome) are baked in and read as English; routing them through the
  catalogue is later-batch work.
- **theme mode is explicit, not system**: upstream's initial
  `GalleryOptions.themeMode` is `ThemeMode.system`; here the default and the
  `--light` flag set an explicit mode, because the headless and test
  platforms report light and following the system would change what every
  screenshot shows. `ThemeMode::System` resolves through
  `platform::brightness()` and is selectable in settings
  (`src/data/gallery_options.rs`, `src/app.rs`).
- **some options resolve but are not rendered**: theme mode, text scale (a
  `MediaQuery` override at the root) and `time_dilation` (the frame clock in
  `Gallery::advance`) are live. Text direction, locale and platform still
  resolve but render nothing — no RTL layout, no locale switching, one
  embedder — and `SystemUiOverlayStyle` has no system chrome to style. The
  settings rows for them are present but disabled, with the reason as the
  subtitle (`src/data/gallery_options.rs`, `src/pages/settings.rs`).
- **backdrop panel duration is desktop's**: upstream's inverted
  `isDesktop ? mobile : desktop` duration is mirrored as written, but
  `GalleryState` is built before any `MediaQuery` exists, so the controller
  always uses the desktop constant (600ms) (`src/app.rs`).
- **settings icon morph is a rotating glyph**: upstream's `SettingsIcon`
  custom painter (gear crosses into a close icon) is drawn here as the gear
  glyph rotating and cross-fading into the close glyph
  (`src/pages/backdrop.rs`).
- **splash effects are a static logo**: upstream's back layer plays a random
  `splash_effect_N.gif`; the image pipeline decodes a GIF's first frame only
  and the effects are not shipped, so the back layer is the Flutter logo on
  the GIFs' background colour (`src/pages/splash.rs`).
- **entrance animation starts finished**: faithful to upstream at d12640d,
  where initState sets the entrance controller to 1.0 whenever the splash is
  already dismissed — which it always is. The stagger machinery is ported but
  never visibly plays (`src/app.rs`, `src/pages/home.rs`).
- **desktop carousel has no snapping physics**: upstream's desktop carousel
  is a scrollable with page buttons; the buttons animate by one card width,
  but there is no snap-to-card physics on a free drag (`src/pages/home.rs`).
- **foldable is always false**: no hinge data in `MediaQueryData`, so
  `is_display_foldable` never fires and the splash's `TwoPane` branch is
  unreachable (`src/pages/adaptive_layout.rs`).
- **demo options section is unreachable**: upstream has 81
  `GalleryDemoConfiguration`s across 42 demos; the catalogue here is
  flattened to one configuration per demo, so the options icon and section
  have nothing to pick (`src/pages/demo.rs`, `tools/gen_catalog.py`).
- **demo code and docs icons are disabled**: code is batch M-H; docs needs
  `url_launcher`, which has no counterpart here. Both icons draw muted with
  no handler (`src/pages/demo.rs`).
- **demo wrapper corners are uniform**: upstream clips the demo card at top
  10 / bottom 2 (`lib/pages/demo.dart`'s asymmetric `BorderRadius`);
  `ClipRRect` takes one radius, so both are 10 (`src/pages/demo.rs`).
- **about dialog is trimmed**: the repository link is coloured but not
  tappable (no `url_launcher`), and "View licenses" is omitted (no
  `LicensePage` in the framework) (`src/pages/about.rs`).
- **feedback link is disabled**: upstream opens an issue tracker URL through
  `url_launcher`; the row draws with the reason as its subtitle
  (`src/pages/settings.rs`, `src/pages/home.rs`).
- **colors/typography lists are height-bounded**: both demos render their
  upstream content -- the colors demo the 2014 palette swatches with
  names/hex values, the typography demo the 2018 type scale with style
  names/sizes -- but each `ListView` scrolls inside a fixed window rather
  than filling the demo screen, and the colors demo's scrollable `TabBar` is
  a horizontal `ListView` (the framework's `TabBar` lays tabs out to equal
  shares). Typography's styles are the scale's values as data (the
  framework's `Theme` carries no typography), in the framework's default
  font rather than Roboto (`src/demos/reference/colors_demo.rs`,
  `src/demos/reference/typography_demo.rs`).
- **2d-transformations is a flex demo**: pan/zoom is not ported; the entry
  shows a layout stand-in (`src/demos/reference/transformations_demo.rs`).
- **two-pane renders its single-pane fallback**: the module is wired into
  `src/demos/reference/` but unrouted -- it is upstream's `DeferredWidget`
  demo and the catalogue excludes it (see "deferred loading is
  synchronous"). What renders is the small-screen configuration's
  list-or-details behavior; the foldable and tablet configurations are not
  rendered (`src/demos/reference/two_pane_demo.rs`).
- **rally donut → bars**: Rally's donut chart is drawn as bars
  (`src/studies/rally/home.rs`).
- **shrine uniform grid**: Shrine's grid sizes tiles uniformly; each
  product's `assetAspectRatio` is carried but not read
  (`src/studies/shrine/model/products_repository.rs`).
- **accent-per-category**: demo row icons are tinted per category instead of
  all `primary` (`src/data/demos.rs`, `tools/gen_catalog.py`).
- **deferred loading is synchronous**: `DeferredWidget` upstream loads a
  deferred component; here the equivalent builds synchronously. (In scope,
  not yet ported — the `two-pane` demo is excluded from the catalogue until
  then; see `tools/extract_catalog.py`.)
- **M-D demos/material batch** (per-file headers carry the full list):
  - Overlay positioning is geometric, not measured: menus/dialogs anchor at
    fixed or computed offsets rather than the trigger's `RelativeRect`
    (`menu.rs`'s `popup_menu_offset` needs an anchor rect the demo stage does
    not have) — app_bar, banner, menu demos.
  - Demo chrome (Scaffold/AppBar) belongs to `src/pages/demo.rs`; demos that
    upstream renders inside their own Scaffold approximate it
    (bottom_app_bar, nav_drawer, nav_rail).
  - Framework widget gaps are drawn locally in the demo: ToggleButtons, FAB,
    chip avatar/delete, `CircularNotchedRectangle` notch (rectangle clips
    only), `NavigationRail` leading/labelType, `TabBar` isScrollable,
    indeterminate checkbox mark, range slider double thumb, SliderTheme
    custom shapes, `InputDecoration` (labels/hints/helpers become
    caption-above/note-below), input formatters (validated, not rewriting).
  - `RestorationMixin` is not carried anywhere (no counterpart); snackbars
    ride inline areas rather than `ScaffoldMessenger` except the snackbars
    demo's own overlay; data-table rows-per-page is two text buttons, not a
    dropdown; places photos ship for grid-lists/cards placeholders where the
    asset exists, slate fill where it does not.
- **M-E demos/cupertino batch** (per-file headers carry the full list):
  - Cupertino demos provide their own `CupertinoTheme` (light, or
    brightness-matched) per stage — upstream wraps them in `DemoWrapper`'s
    ambient `CupertinoTheme`; the demo page here only provides the Material
    demo theme.
  - Stages are height-bounded constants and modals (alerts, context menu,
    picker sheets) render in the stage's own stack, not a shared overlay —
    the shared `overlay()` dispatch can only see `GalleryState`, and per-demo
    state lives in per-demo StatefulComponents.
  - Framework-tier gaps approximated in the demos: `CupertinoActionSheet` →
    `CupertinoAlertDialog`; `CupertinoDatePicker`/`CupertinoTimerPicker` →
    rows of single-field `CupertinoPicker` wheels; `CupertinoSlidingSegmentedControl`
    → locally drawn stand-in (no slide animation); `CupertinoSliverNavigationBar`
    → plain bar + in-body large title; tab-bar icons are letter marks and
    tab icons drawn glyphs (no icon font in the tier); context-menu child is
    the logo asset, not a drawn `FlutterLogo`; no zoom/blur/drag-to-dismiss
    on context menus; scrollbar custom thickness/radius unexpressible;
    `editable::TextField` derives placeholder color from the ambient material
    theme, so cupertino placeholders read dark-on-dark in dark mode.
  - "Now" values are UTC (`pickers::Date::today` convention).
- **M-F demos/reference batch**:
  - colors/typography now show upstream's Material 2014 palette / 2018 type
    scale content (rewrites); lists are height-bounded constants (the demo
    stage offers no bounded height); the colors tab strip is a horizontal
    ListView (framework TabBar can't scroll).
  - two_pane renders its small-screen single-pane fallback only (foldable
    is always false); it is wired but unrouted — upstream lists it under a
    DeferredWidget demo the catalog generator deliberately skips.
  - transformations got a real framework `InteractiveViewer`
    (`rustflutter/src/interactive_viewer.rs`, ported from
    widgets/interactive_viewer.dart): Matrix4 collapses to a 2D affine, no
    rotation (upstream hardcodes it off too), no scale inertia, no trackpad
    branch. The demo itself: fixed 380×480 viewport, edit panel in-stage
    rather than a modal bottom sheet, board drawn as filled paths not
    Vertices fans, Reset lerps translation+scale rather than Matrix4
    decomposition.
- **M-F motion demos**: the six upstream motion patterns are six sections on
  the single `motion` stage (the flattened catalog has one slug); each
  pattern's route is section-local state; the `animations` package's
  transitions are re-implemented with framework Controllers (opacity/scale
  choreography per the package's specs). Per-file headers carry the rest.
